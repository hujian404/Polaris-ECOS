# Regular-clock spatial proxy

This is a synthetic clock-only diagnostic using **4096 real DFFQX0P5H7R cells** on a regular grid in the course candidate's die. It keeps the original clock-port location and obtains cell/clock-pin names from the real H7CR Liberty. Data pins are omitted. It is **not an electrical reduction, processor implementation, or signoff test**.

The observed 64x64 case reproduced regular-domain strict root-boundary failure in about **11 seconds**, avoiding the full design's roughly 38-minute DEF import. This is evidence of a similar failure class, not proof that every cause or parameter result transfers to Polaris. Native validation used the isolated source build from [run 40156959057](https://github.com/hujian404/Polaris-ECOS/actions/runs/40156959057).

Start from the nine-macro project generated by the PDK-free materializer in [ECC #357](https://github.com/openecos-projects/ecc/issues/357), or the existing course nine-macro fixture. The generator reuses its configuration and external dependency paths; those paths, including unused SRAM views in the template, must remain valid. It does not embed Liberty, LEF or SRAM IP files. Use the documented ICS55 H7CR/H7CL library version and a fresh output/workspace.

```sh
python3 repro/regular-clock-spatial/generate.py \
  --template /path/to/nine-macro-project \
  --pdk "$CHIPCOMPILER_ICS55_PDK_ROOT" \
  --out /tmp/regular-clock-project --grid 64
ecc check --project /tmp/regular-clock-project
ecc run --project /tmp/regular-clock-project \
  --workspace /tmp/regular-clock-run --from CTS --to CTS
```

The tested template uses 50MHz, max_cap=0.45pF, root slew=0.05ns, max sink transition=0.4ns, max buffer transition=0.5ns, skew target=0.08ns, and BUFX8/12/16/20H7L. Confirm these in the native runtime log when using another tool version. `generation.json` records the generated inputs' identities. No synthesis/program-functional result is implied by an unconnected data path.

Observed first rejected samples: compensation valid, cap bucket match true, slew bucket match false; raw cap=13, total physical load=30, source boundary=8, raw input slew=1, root output slew=20. These are bucket indices. Only one rejected sample per explored depth was logged; they do not describe every rejected candidate. The full processor separately returned total-load/root-slew buckets 32/22. All seven full-design depth candidates were rejected. See [ECC #357](https://github.com/openecos-projects/ecc/issues/357) for the native diagnostic context; the separate source-trunk connection correction is [draft PR #319](https://github.com/openecos-projects/ecc-tools/pull/319).
