# SRAM 配置的流程推进与当前完成边界

本轮有限实验已经结束，计算进程已释放，50 份日志、配置和产物在本地逐文件校验通过。**SRAM 配置完成 CTS 与合法化，但布线达到六小时外部上限，尚无最终布线 GDS 或签核结论。** 无缓存配置的 `v1.0.0-cacheless` 冻结结果独立成立。

## 布线规模与停止位置

路由器先后完成约 285 万条网络的初始 LZ 和拥塞 LZ 子阶段，然后处理 677,888 条存在溢出的网络。最后检查点是 `overflow All pattern` 的 610,100 / 677,888（90%）。这个百分比只对应平面路由中的一个子过程，**不表示整个布线流程已完成 90%**；后续层分配、轨道分配和详细布线还未执行。

核对与实际 native 模块对应提交的源码后，`PlanarRouter::routePRNetList` 对该网络列表逐条处理，`runRouteFlow` 之后还包含最多五轮固定的 A* 拥塞修复。32 线程配置不能据此解释为该子过程已有 32 倍并行度。当前公开路由配置中未找到可直接跳过或限制该子过程的快速开关。本轮保持原算法语义，在资源预算处停止，不重复相同配置长跑，也不据此外部终止断言设计物理不可行。

## 可继续使用的检查点

后续可从已验证的合法化网表、DEF 与原 50 MHz SDC 继续研究路由性能和局部拥塞，无需重复 Chisel 生成、综合、布局或 CTS。保留匹配的 golden 与全部交接摘要；不得以其他配置的 DRC/LVS 或十三角时序结果替代本配置验证。

[CTS 局部表优化与对照](cts-local-cap-subset-candidate.md)对应的 [PR320](https://github.com/openecos-projects/ecc-tools/pull/320) 已获维护者批准，当前提交的 Python API、Wheel、Nix 与提交规范检查均通过，尚未合并。该优化解决复制工作量问题，不代表时钟质量或完整物理流程闭合。
